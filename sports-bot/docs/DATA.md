# Offline intelligence data guide

The bot does not require administrators to build teams, rosters, injuries, travel context, or historical results by hand. Its shared private provider cache automatically supplies supported active leagues with historical finals/boxes, compact play-by-play, and upcoming games with available injury, roster, lineup, probable-starter, official-source, environment, and free-line evidence. A local venue table supplies travel/time-zone/altitude context. The per-guild intelligence store is an optional override layer for facts that are missing, newer, or more precise. It contains five collections: teams, players, contexts, games, and results. JSON bundle imports may contain any combination. CSV imports contain one collection at a time and require the matching kind in `/sportsdata import`.

## Automatic versus manual precedence

- Automatic historical results derive team power, opponent-adjusted strength, schedule strength, offense, defense, recent form, rest/congestion, recent head-to-head, season regression, and Elo updates.
- Selected immutable historical boxes and compact plays derive sport-specific efficiency, player value/form/participation/starter rate, shrunken starter-pair interactions, success/explosiveness, pressure/turnover, and shot-quality evidence when available.
- Automatic event summaries derive current injuries, roster/lineup coverage, probable starters, projected participation/workload, officials, roof/surface/weather context, and an optional free single-book line.
- Local venue geometry derives travel distance, daylight-saving-aware time-zone shift, altitude change, and fatigue; historical probable starters supply available days-since-last-start evidence; supported keyless MLB/NHL feeds and the nflverse NFL schedule dataset provide independent event corroboration.
- A matching manual team, player, or context record overrides the automatic record or matching fields for that game.
- Automatic evidence contributes to API Confidence. Only per-guild server-owned records contribute to Local Data Confidence.
- Automatic data carries `autoGenerated`, source, update time, cache state, and sample counts in the frozen slate for auditability.
- No current-game box-score statistic is used to build a pregame feature.

Because public injury and lineup coverage varies by league, `/sports game` should be checked for confirmed sides, projected workload, learned-player/pair coverage, play-by-play coverage, automatic injury counts, source conflicts, and missing inputs before relying on an absence-sensitive prediction. Manual entry is most valuable for a very late scratch, unannounced starting goalie/QB, private projected-minutes information, verified travel disruption, coaching change, or matchup fact not present in public feeds.

Use /sportsdata schema to download a current example from the running bot. Use /sportsdata export before large changes.

Every successful intelligence/settings write is atomic and preserves the previous file as a .bak sibling. Corrupt JSON fails closed instead of being replaced with an empty store. If recovery is needed, stop the bot, preserve both files, validate the backup, then restore it outside the public web root.

## Team scaling

Use a consistent league-relative scale. A practical 0-100 convention is:

- 90-100: historically elite/title-level.
- 75-89: strong contender.
- 60-74: above average.
- 45-59: near average.
- 30-44: below average.
- 0-29: severely weakened or lower tier.

Do not compare a 75 in one league directly with a 75 in another. Re-rate teams after roster, coaching, or competition-level changes. Notes should state the source and update date.

Defense is always higher-is-better. Convert metrics such as ERA, goals allowed, or defensive rating before entering them so the direction stays consistent.

## Player impact and availability

Impact uses -10 to +10. Most players should be between 0 and 4; values above 7 should be reserved for athletes whose absence materially changes the event probability. Negative impact is allowed for a known adverse lineup effect but should be rare.

Availability is the estimated chance/extent of participation, from 0 to 100. It is combined with historical participation and starter/workload evidence; it is not automatically treated as the percentage of a full workload. Status text maps common states conservatively:

- out, inactive, suspended: 0%.
- doubtful: 25%.
- questionable or game-time decision: approximately 52%.
- probable or limited: approximately 82%.
- available: the explicit availability field, normally 100%.

Explicit availability should be updated near prediction time. The engine applies extra importance to starters and sport-critical roles.

Automatic injury rows use conservative status mappings. When the athlete matches cached historical boxes, impact, form, participation rate, starter rate, and any compatible workload history come from reliability-shrunk evidence; otherwise the engine uses a conservative position/starter fallback. Current confirmed lineups also measure expected-player coverage, continuity, and recurring starter-pair residuals. Manual player records take precedence when an administrator supplies better impact, availability, role, or current status. Do not add a manual context penalty for the same injury unless you intentionally want an additional effect; that would double-count it.

Recognized optional stat examples:

| Sport | Stats |
| --- | --- |
| Baseball | war, era |
| Basketball | plusMinus, minutes |
| Football | epa; role should identify quarterback when applicable |
| Hockey | goalsAboveReplacement or gar, savePct |
| Soccer | rating, xg, xa |
| Tennis | ranking |
| Combat | strikingDifferential |

Explicit impact remains preferable to mixing raw stats from incompatible leagues or providers. Stats are intentionally bounded so an anomalous field cannot dominate the model.

## Context factors

Objective fields may use natural units:

- homeRestDays, awayRestDays
- homeTravelKm, awayTravelKm

Subjective fields should normally use -1 to +1:

- homeFatigue, awayFatigue
- homeMotivation, awayMotivation
- homeMatchup, awayMatchup
- homeStyleMatchup, awayStyleMatchup
- weatherSeverity from 0 to 1
- homeWeatherFit, awayWeatherFit
- homeSurfaceFit, awaySurfaceFit
- homeTravelDisruption, awayTravelDisruption
- homeCoachingChange, awayCoachingChange

Automatic context may also retain roof, surface, temperature, wind speed/direction, precipitation, and referee/official identifiers when exposed. These text/environment fields support auditing and bounded automatic adjustments; arbitrary unknown text does not silently change a probability. Official profiles are observational, reliability-shrunk league comparisons and should never be entered as guaranteed bias.

Direct homeAdjustment and awayAdjustment accept -2 to +2 and should be used sparingly for important information that cannot be represented elsewhere. Using a direct adjustment to repeat an injury already present in players double-counts it.

Set expiresAt on game-day contexts so stale injuries or weather do not carry into a later event with a reused provider ID.

## Manual schedules and strict local mode

Games require league, awayTeam, homeTeam, and startTime or dateKey. Use ISO 8601 timestamps with an explicit UTC offset whenever possible. leagueKey should match a supported key for the correct sport profile, such as nba, wnba, ncaab, ncaaw, mlb, nfl, ncaaf, nhl, epl, ufc, atp, or wta. sportGroup may be Baseball, Basketball, Football, Hockey, Soccer, Combat, or Tennis.

In LOCAL_ONLY=true mode, manual games are the schedule. Final results must be imported or added with /sportsdata result-add.

With normal networking enabled, `AUTO_ENRICH_ENABLED=false` disables history, box-score, play, lineup, official-source, and situational enrichment while leaving the daily scoreboard available. Request limits and freshness windows are configurable with `AUTO_SUMMARY_MAX_GAMES`, `AUTO_SUMMARY_CACHE_MINUTES`, `AUTO_HISTORY_MAX_LEAGUES`, `AUTO_HISTORY_CACHE_HOURS`, `AUTO_HISTORY_MAX_DAYS`, `AUTO_BOXSCORE_MAX_EVENTS`, and `AUTO_BOXSCORE_CACHE_DAYS`. `AUTO_OFFICIAL_SOURCES` controls keyless MLB/NHL checks; `SOURCE_REDUNDANCY_ENABLED` controls additional independent schedule corroboration; `PLAY_BY_PLAY_ENABLED` controls compact play retention; `LOCAL_ML_ENABLED` and `LOCAL_ML_MIN_SAMPLES` control the trainable shadow challenger. Defaults favor broad daily usefulness while ensuring repeated guild refreshes reuse the same shared cache.

## CSV

CSV headers use the same field names. Nested stats/factors must be JSON text inside a quoted CSV cell. Examples are in examples/teams.csv and examples/players.csv.

## Data hygiene checklist

- Use canonical team names consistently; add aliases for provider variations.
- Prefer automatic coverage first; add manual rows only when they are more current or precise.
- Do not import duplicate results under different spellings.
- Preserve historical data; do not rewrite past inputs after seeing outcomes.
- Timestamp notes for injuries, lineups, and weather.
- Keep rating scales stable within a league.
- Avoid double-counting the same fact across team, player, and context records.
- Export a backup before bulk imports.
- Recalculate the current slate, then inspect /sports game signals for the expected direction.
- Use /sportsdata evaluate before interpreting any high confidence as trustworthy.
